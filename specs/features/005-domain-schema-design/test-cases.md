# Schema-specific acceptance and failure test design

Status: **PLANNED — NOT IMPLEMENTED OR EXECUTED**. Scenario labels SC-01 etc. are local design labels, not new canonical acceptance IDs or passing results. Existing IDs below come from `tests/test-catalog.csv`. Documentation verification is separately recorded in [evidence.md](evidence.md).

Future implementation must first demonstrate RED for the approved slice on an isolated disposable PostgreSQL 17 target. Failing imports alone do not prove a concurrency/integrity invariant; capture behavioral failures before implementing each relevant service/constraint. Never mutate/reset the existing readiness database for these tests. Real concurrent PostgreSQL transactions, not only mocks, must prove locks/constraints.

All authorization cases include guest, unverified/suspended user, wrong role, wrong owner, wrong organization, wrong district, revoked grant and stale session as relevant; safe denial returns no hidden-object, SQL, token, contact or location details. Each mutation case also verifies zero unauthorized domain/audit/notification/outbox/replay success effects.
